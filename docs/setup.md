# Setup

## Prerequisites

- Node.js 20+
- npm 10+
- Expo CLI through `npx expo`
- Supabase CLI
- A Supabase project or local Supabase stack

## Install

```bash
npm install
```

## Environment

Copy `.env.example` into the app-specific env files:

```bash
cp .env.example .env
cp .env.example apps/mobile/.env
cp .env.example apps/admin-web/.env.local
```

Set:

- `SUPABASE_URL`
- `SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`
- `EXPO_PUBLIC_SUPABASE_URL`
- `EXPO_PUBLIC_SUPABASE_ANON_KEY`
- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- `EXPO_ACCESS_TOKEN` when push delivery is enabled

Never place `SUPABASE_SERVICE_ROLE_KEY` in the mobile or web client env files.

## Database

For local Supabase:

```bash
supabase start
supabase db reset
```

For a remote project:

```bash
supabase link --project-ref your-project-ref
supabase db push
supabase functions deploy submit-attendance
supabase functions deploy review-attendance
supabase functions deploy generate-qr
supabase functions deploy send-notification
supabase functions deploy verify-student-registration
supabase functions deploy resolve-student-login
```

Seed sample data:

```bash
psql "$SUPABASE_DB_URL" -f supabase/seed/seed.sql
```

## Run Mobile

```bash
npm run dev:mobile
```

Use Expo Go for simple testing or a development build when testing camera, maps, notifications, and native configuration.

## Run Admin

```bash
npm run dev:admin
```

Open `http://localhost:3000`.

## Auth Accounts

Admins still create their own Supabase Auth users and matching rows in:

- `public.users`
- `public.admin_profiles` for admins

Students register from the mobile app. Before registration, import the approved CSU Gonzaga CBEA roster from the admin `/students` page or directly into `public.approved_student_roster`.

Required roster CSV columns:

- `student_id`
- `school_email`
- `full_name`

Optional columns:

- `year_level`
- `status`

Student registration is activated only when:

- the submitted student ID matches `approved_student_roster.student_id`
- the submitted school email matches `approved_student_roster.school_email`
- the roster row is CBEA and `eligible`
- the Supabase school email confirmation is completed
- the roster row is not already claimed by another auth user

Student ID login is resolved by the `resolve-student-login` Edge Function. The mobile app no longer maps IDs to fake `@students.local` emails.

## Mobile confirmation and password recovery

The app sends confirmation and reset emails with an `auth-callback` return URL generated by Expo Linking. The callback validates the email session in a separate, memory-only Supabase client. Recovery links open the new-password form without signing the student into attendance. Confirmation links return the student to sign in, where roster and account checks still apply.

Before testing real email delivery:

1. Enable email confirmation in Supabase Auth and configure email delivery for your student recipients. The default Supabase email service has recipient restrictions and is not suitable for campus deployment; configure your school's SMTP service.
2. In Supabase **Authentication → URL Configuration → Redirect URLs**, allow the exact callback URL used by the app. For an installed native build with the existing scheme, this is `attendance://auth-callback`.
3. For Expo Go, also allow the development callback URL, for example `exp://192.0.2.1:8081/--/auth-callback`, substituting the address and port printed by your Expo server. Update this entry when the development address changes. Open emails on the phone running that app. For web testing, allow that server's `/auth-callback` URL too.
4. Keep the signup and recovery email templates using Supabase's `{{ .ConfirmationURL }}` so the verification endpoint validates the token before returning to the app. These screens support the default JavaScript implicit-flow callback, including its `type`, `access_token`, and `refresh_token` parameters. Custom PKCE or token-hash templates require a corresponding callback implementation.
5. Optionally set `EXPO_PUBLIC_CAMPUS_SUPPORT_EMAIL` in `apps/mobile/.env` to the school's actual support mailbox and restart Expo (rebuild for releases). If it is absent, the help screen directs students to the CBEA office without displaying a fabricated contact.

Verification resend and password reset require the registered school email. Editing that field changes the recipient being requested; it does not change an account's email address. Incorrect registration details should be corrected by authorized campus staff after identity verification. The 60-second resend countdown is a UI safeguard; Supabase's server-side limits remain authoritative.

References: [Supabase mobile deep linking](https://supabase.com/docs/guides/auth/native-mobile-deep-linking), [redirect URLs](https://supabase.com/docs/guides/auth/redirect-urls), and [email delivery](https://supabase.com/docs/guides/auth/auth-smtp).
